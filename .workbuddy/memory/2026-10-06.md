## Bug 修复：content.js:723 `Cannot read properties of undefined (reading 'name')`

- 原因：`app` 全局只在后台（app_bg.js）赋值，内容脚本环境（includes/app.js）只声明未赋值，
  sieve 规则编译失败走 `console.error(app.name + ...)` 时抛 TypeError。
- 修复：includes/app.js 中 `platform.crx = true` 后用 `chrome.runtime.getManifest()` 初始化 `app = {name, version}`，并用 try/catch 兜底。

## Bug 修复：CSP 禁止 eval 导致 JS 型 sieve 规则每次悬停报错

- 现象：YouTube 等严格 CSP 页面（script-src 无 'unsafe-eval'，且页面 CSP 对内容脚本同样生效，MV2 时代即如此），
  content.js 两处 `Function()` 动态编译（toFunction:719、resolved 处理:2617）每次悬停都抛 CSP 错误刷屏。
- 约束：JS 规则中 20/106 依赖 `this`(PVI) 与 DOM（document.evaluate 等），无法搬到 Service Worker 或沙箱 iframe（无 DOM 且 MV3 也禁 eval），
  只能优雅降级。
- 修复：新增 `PVI.evalBlocked` 标志——首次捕获 EvalError/CSP 错误时置位并 `console.warn` 一次，
  之后 toFunction 直接返回 false、res===1 的规则直接按 `d.m=false` 回退（走 IMGS_fallback_zoom/直接链接放大），
  不再重复报错、不再闪 R_js。正则型规则不受影响。
- 降级路径已核实：replace() 返回 1 → find() 返回 1 → m_over 中 `src===1 → src=false` 回退。

## 真正修复：MV3 内容脚本继承扩展 CSP（禁 eval）→ sieve JS 规则预编译

- 用户确认 MV2 下 YouTube 上 JS 规则可用。查证：MV2 内容脚本**没有 CSP**（eval 可用）；
  MV3 内容脚本继承扩展默认 CSP（`script-src 'self' 'wasm-unsafe-eval'` + Chrome 附加源，报错信息中的
  chrome-extension://<id> 是本扩展自身 ID），且 MV3 不允许放宽该 CSP —— 全站都会拦 eval，属 MV3 硬性回归。
- JS 规则作为 `String.replace` 的同步替换函数被调用（_replace: `addr.replace(rule[param], to)`），
  无法改异步桥（userScripts/sw），因此采用**预编译**方案：
  - `tools/build-sieve-rules.js`：解析 sieve.jsn，把 `to`/`img`(非内联函数体)、`url`(内联 return)、
    `res`(function($)) 三类 JS 规则生成为真实函数，key 为 `param + "\u0000" + 原始代码串`（res 用剥前缀后的串），
    生成 `includes/sieve_rules.js`（113 条，59KB，含 `izRuleFn(param, code)` 查找器）。
  - manifest 第一个 content_scripts 条目注入 `includes/sieve_rules.js`（document_start，同一隔离世界共享全局）。
  - content.js `toFunction` 与 resolved 处理（原 2617 处）优先 `izRuleFn` 查表并 `.bind(PVI)`；
    查不到（如自定义存储 sieve）才回退 `Function()`，仍被 CSP 拦则走 evalBlocked 降级。
- 验证：/tmp/verify_sieve_rules.js 用 vm 加载生成的文件，对全部 113 条与 `Function()` 编译版
  在 4 组样例输入下逐条对比（含异常路径），0 不一致；`node --check` 全过；manifest JSON OK；后台冒烟测试复跑通过。
- 版本 1.2.0 → 1.2.1。改动生效需在 chrome://extensions 重新加载插件。
